Privacy and cleanup settings
Cleanup mode

Standard mode keeps cleanup targeted to the selected site. Expert mode enables configurable expanded and destructive options.

Cleanup review is always required

Standard and Expert cleanup both show a fresh, read-only summary of the exact scope, configured effects, known limits, impact counts, private-window reach, and any file deletion. Cleanup cannot start until you review that summary and explicitly approve the run.

Keep local cleanup history

Stores recent SiteWipe reports in chrome.storage.local for side panel review. Off by default in the performance build; the latest report is still shown after a run.

Report retention

When local cleanup history is enabled, automatically prunes reports older than this window before saving a new report. The latest report is still shown after a run unless you forget it.

Auto-forget latest report

The latest locally stored report is redacted by default and expires after 30 minutes. Choosing indefinite retention is an explicit privacy opt-in. Cleanup history retention controls the separate history list.

Browser permission rules stay under your control

SiteWipe no longer adds default-like browser permission or content-setting rules, because they can override intentional user, policy, or other-extension choices. Existing SiteWipe-owned rules from earlier releases are cleared when you upgrade.

Preserved
Run browser cookie sweep

After enumerating and deleting matching cookies directly, also asks Chrome to remove target-domain cookies through origin-scoped browsingData cleanup.

Include installed/protected site data

Also cleans protected web origins for the target, such as installed app/PWA data. Off by default because it doubles some browsingData cleanup work.

Scrub live page storage before closing tabs

Injects a one-time cleanup pass into matching open pages and frames to clear page-visible sessionStorage, localStorage, Cache API entries, IndexedDB databases, Storage Buckets, visible cookies, and service worker registrations before tabs close.

Delete live Storage Buckets

When the selected site exposes the Storage Buckets API in an open page, deletes those buckets during the live scrub. Off by default because some pages expose slow bucket operations.

Discover embedded target frames

Optional deeper scan: checks open tab frames so SiteWipe can clean target data loaded inside iframes on other pages. Off by default for better performance.

Probe partitioned cookies by embedding site

Optional deeper scan: uses discovered top-level pages that embedded the target as additional partition-key probes for CHIPS/partitioned cookie deletion. Off by default for speed.

Exhaustive preflight-bound target cookie scan

Slow opt-in mode: enumerates cookies exposed under the temporary preflight-bound target permissions before applying the same target matcher. It does not grant access to unrelated sites.

Use capped recent-download fallback

Searches a small recent slice of all download records after normal domain queries. Off by default for speed; enable only if normal download cleanup misses records.

Verify exposed residue after cleanup

After a normal cleanup, re-checks exposed cookies, open target tabs, history URLs, and download records. On by default; no hidden browser internals are claimed.

Use broad history/download fallback terms

Optional performance tradeoff: after precise domain searches, also queries the registrable first label such as example. Off by default because short or generic labels can create huge result sets.

Block target requests during cleanup

Uses MV3 Declarative Net Request session rules to stop the target from immediately recreating storage while SiteWipe is running. On by default.

Show cleanup progress on pages

Draws a small bottom-right progress overlay in accessible http/https tabs while SiteWipe is running, updates it between cleanup phases, then removes it when cleanup finishes. Restricted pages such as chrome:// cannot be overlaid.

Show cancel button in progress overlay

Adds a Request cancel button to the page overlay. Cancellation is cooperative: SiteWipe stops before the next major phase rather than interrupting a destructive browser operation mid-call.

Progress overlay scope

Choose where the page overlay appears during a cleanup. Target tabs is quietest but may disappear once matching tabs are closed.

Keep target blocked until browser restart

Optional post-wipe shield: leaves the target-domain session request block active after cleanup. Off by default because it can break sites until disabled or the browser restarts.

Post-wipe shield expiration

When the post-wipe shield is enabled, optionally clear SiteWipe's target block after a short local timer instead of waiting for browser restart.

Reset saved site zoom

Resets open target tabs to the browser default zoom factor before tabs are closed, which clears Chrome's per-origin zoom memory for those tabs.

Reset muted target tabs

Optional: unmutes target tabs before closing them. Off by default because muting can be an intentional user preference.

Unpin target tabs

Optional: unpins target tabs before closing them and records pin/group/window details in the report.

Delete OPFS data from live pages

Uses navigator.storage.getDirectory() in matching open pages where available to remove Origin Private File System entries, capped for performance.

Clean push and sync registrations

Before unregistering service workers, tries to unsubscribe push subscriptions and unregister periodic-sync tags. One-off Background Sync tags are recorded as evidence because the web API has no tag-level unregister operation.

Clear PWA/app badge

Calls navigator.clearAppBadge() in matching live pages where supported.

Audit live page permissions

Queries page-visible permission states such as notifications, camera, microphone, geolocation, clipboard, MIDI, and persistent storage when supported.

Delete matched downloaded files from disk

Optional destructive mode: removes completed files on disk for matched target download records, then erases those download-history entries. Leave off unless you want SiteWipe to delete files.

Autofill and payment methods are protected

Chrome couples global form-data cleanup with saved autofill profiles and payment cards. SiteWipe does not call that profile-wide removal API because it cannot safely delete autofill while preserving payment methods.

Protected
Redact stored cleanup reports

Safe default. Removes target domains, URLs, referrers, filenames, local paths, extension IDs, and sensitive free-form error text before local storage. Turning this off stores sensitive browsing details and requires informed opt-in.

Advanced and diagnostic settings
Allow exact-origin localhost/IP cleanup

Advanced developer mode for local apps and IP-address targets. Requires a full http/https origin such as http://localhost:3000. Tabs/storage/history/downloads match the exact origin; cookies are host-scoped because browser cookies are not port-scoped.

Block cleanup when associated groups have errors

Safer default: if associated-domain group syntax has errors, SiteWipe stops before any cleanup instead of silently cleaning only the primary target or a partial group.

Associated-domain cleanup groups

Optional advanced mapping for configured related domains. Use one group per line: primary.example => cdn.example, login.example. When the primary is cleaned, the associated targets are included too.
