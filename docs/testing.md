## Local commands

Use exact Node.js 24.18.1 with its bundled npm 11.16.0 for candidate evidence. Broader Node.js 24/npm 11 support remains a development compatibility floor, not authority to mix toolchain bytes in one release transaction.

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm run check
npm run test:coverage
npm audit --audit-level=low --json
npm run browser:fixture
npm run build:release-candidate
npm run verify:release-candidate
npm run verify:reproducible-release-candidate
```

The build and verification commands are listed for discoverability; they are commit-bound release operations, not one dirty-worktree sequence. Follow the clean source/evidence commit boundaries in [`releasing.md`](./releasing.md).

The Node runner executes test files serially. Several files independently model extension service-worker lifecycles with deliberately bounded browser-operation timers; file-level parallelism under coverage instrumentation can otherwise starve one model behind unrelated work and create a host-contention timeout. Assertions inside each file, product timeouts, and coverage thresholds are unchanged.

`npm run check:publication-gates` is deliberately separate and expected to fail until human and remote evidence exists. It reruns version/source and exact runtime/source artifact verification in-process even when invoked by itself; a failure there is an accurate release status, not a failing unit test.

## Synthetic fixture infrastructure

`tests/browser/fixture-server.mjs` serves only on loopback by default. Its host-aware page can seed bounded localStorage, sessionStorage, IndexedDB, Cache Storage, service-worker cache, Storage Bucket, OPFS, ordinary/partitioned-cookie attempts, and a harmless download where the browser exposes each API. Small, medium, and large page-store scales are deterministic. The non-reseeding route is a partition-observation probe, not a preservation oracle: registrable-site browser cleanup should clear persistent third-party page storage partitioned beneath the selected top-level site, while a separate unrelated-top-level partition and the out-of-domain CHIPS cookie remain. SessionStorage is recorded separately because it follows the browsing context. See `tests/browser/README.md` for disposable-profile host mapping, exact-origin browser-storage skips, and secure-context limitations.

The fixture server has Node contract tests and loopback HTTP routes that serve the real popup, Options page, and side-panel HTML/CSS/JavaScript, with a surface-specific synthetic browser-API mock injected ahead of each production module. The popup route covers detailed/direct, private/pregranted/transient, permission-denial retry, unsupported-tab, overlay-disabled, and narrow zoom states; the side-panel route covers report tabs, filters, history, runtime errors, verified zero, known residue with unknown totals, incomplete verification, redaction, and bounded-width states; Options covers the production information architecture plus fail-closed initial hydration and recovery with synthetic storage and permission responses. Exact routes and query controls are documented in `tests/browser/README.md`.

A ChatGPT in-app Browser visit to any of those routes must be recorded as **synthetic in-app UI evidence**, not as an installed-extension run. It can support layout, responsive reflow, accessible structure, keyboard/focus flow, and copy review only. Neither fixture infrastructure nor an in-app Browser page loads the runtime ZIP or a `chrome-extension://` origin, changes Chrome/Brave or installed-accessibility status from pending, or supplies native permission-prompt, incognito-spanning, destructive-operation, privileged browser-API, MV3 lifecycle, exact-artifact performance, compatibility, or authentic store-media evidence.

The unattended installed-browser harness is a separate, fail-closed evidence system. Before creating owned state, its plan binds a clean committed source/tree, canonical runtime ZIP, complete Chrome and Brave runtime closures, trusted Git/Node/PowerShell/helper hashes, exact package lock, installed Puppeteer closure, fixed non-maximized geometry, canonical matrix and semantic-validator manifest. Built-in strict ZIP inspection and exact import-graph checks prove that the staged browser bootstrap loads only the verified installed runtime/toolchain closure rather than resolving an ambient package. Each canonical browser/scenario cell receives a new marked profile and must-preserve synthetic download canary. The runtime validates the exact cell and ownership marker while the profile is still pristine, records that bounded prelaunch fact in the private launch receipt, and lets a later scenario revalidate ownership without mistaking browser-created post-launch profile entries for prelaunch contamination. Both loopback fixture listeners share one post-approval secret and port; the browser is routed through a deny-by-default proxy with exact host/route/method ledgers.

Each cell directly spawns one owned pinned browser over a CDP pipe and registers cleanup ownership immediately after spawn, before PID or pipe validation. Exactly one central bounded graceful-close attempt owns normal closure; scenario hooks receive a safe facade with no raw browser/page `close` or `disconnect` authority, and later cells cannot continue while closure remains unresolved. If graceful closure fails, only the exact owned PID/path/hash/profile/start-time identity may enter bounded leaf-first fallback tree termination, followed by a second zero-residue observation. Any direct-close, fallback, process-identity, cancellation, or residue uncertainty invalidates otherwise passing evidence. Unsupported assertions remain `not_run`, failed observations remain failed, and network/process teardown uncertainty likewise discards otherwise claimable success. All launch, hook, finalizer, helper, and child-process phases are bounded. Completion or fatal-failure settlement is single-use, retains the exact owned run, releases only its identity-bound active lock, and performs no recursive profile, evidence, or downloaded-file deletion.

Raw plans, profiles, helper observations, tokens, browser paths, base64 records, and complete aggregates remain in the ignored owned run. Tracked browser evidence may contain only mechanically replayed path-free commitments and semantic receipts. The public receipt must bind all 48 ordered records, the exact artifact/browser/toolchain identity, the aggregate and result-set hashes, and every assertion to its exact current semantic-manifest validator identity. A canonical `null` identity is permitted only for an explicitly unimplemented assertion that remains `not_run`; stale, invented, missing, or null-plus-passing identities are refused. A public result is admissible only after an immutable create-only canonical finalization manifest has been derived from and reread as the exact canonical on-disk bytes, the supplied object equals that disk object, two complete allowlisted evidence inventory passes agree on bytes/hashes/identity, and final directory/manifest identity replay succeeds. An existing canonical manifest is never overwritten. Digest-only records do not create a pass: any missing validator, missing observation, unsupported API, ambiguity, timeout, failed predicate, incomplete teardown, or absent exact binding remains `failed`, `limited`, or `not_run`. Automation always leaves human `reviewerApproval` false.

The installed run has two deliberately separate commands. `npm run browser:installed:plan -- --workspace-root <absolute-external-directory> --plan-output <absolute-new-json-file>` creates one canonical plan without approving or running it. A later `npm run browser:installed:run -- --workspace-root <the-same-directory> --plan-input <that-exact-json-file> --approval-sha256 <the-plan-SHA-256> --result-output <absolute-new-json-file>` independently rereads and revalidates the plan before launching. The wrapper derives repository and browser authority from committed policy, rejects authority-bearing environment overrides, uses create-only outputs, retains raw evidence under the owned external run directory, and emits only a path-free public summary.

## Integration-test safety rules

1. Create a new browser profile in a test-output directory excluded from Git.
2. Do not sign in or enable Sync.
3. Do not import browser data.
4. Serve fixtures from synthetic local hostnames or loopback ports; never use personal sites.
5. Create only disposable cookies, storage, history entries, records, and files.
6. Record the exact unpacked source tree or ZIP SHA-256.
7. Assert the unrelated control fixture before and after every destructive run. For partitioned page storage, distinguish the disclosed target-associated partition beneath the selected top-level site from a partition beneath an unrelated top-level site; the former is expected to clear for registrable-site cleanup and the latter must remain. Also assert the separately host-scoped out-of-domain CHIPS cookie, and do not use SessionStorage alone as persistent-partition evidence.
8. Inspect `chrome.declarativeNetRequest.getSessionRules()` for owned IDs after every terminal path.
9. Delete the disposable profile only after retained redacted evidence has been copied to `docs/evidence/`.
10. Label ChatGPT in-app Browser results as synthetic UI evidence. Never copy them into installed Chrome/Brave, incognito, native-prompt, MV3-lifecycle, or destructive-API result fields.
11. Freeze the exact source tree before an installed run. Do not test from a live unpacked directory while its files are changing. After any source/version change, close every SiteWipe popup and Options page, use the browser's explicit **Reload** control for the unpacked extension, reopen the UI, and verify the manifest version before preparing detailed or direct authority. A popup and service worker loaded from different source states is not exact-version evidence; discard the run and start with a fresh preflight.

## Failure injection

Browser adapters accept injected dependencies in unit tests. Installed-browser failure injection should use test-only fixture controls or controlled extension reload/worker termination; never weaken production guards. A timeout result must state that the underlying operation may still be running.

## Coverage interpretation

The repository enforces minimum overall coverage of **80% statements, 80% lines, 55% branches, and 70% functions**. Exact current percentages belong in the active automated-evidence record rather than this stable policy document. Browser-dependent adapters and the service worker still require installed-browser evidence regardless of aggregate coverage. Low-value percentages do not waive missing installed-browser branches.

Coverage is a navigation aid, not a safety score. Pure shared modules are expected to have high branch coverage. Browser adapters and the service worker require installed-browser coverage/evidence, so a single repository-wide percentage can be misleading. Any threshold should be split by testable layer and must not exclude files merely to inflate the number.

## Evidence retention

Automated CI logs, coverage, integration JSON, screenshots, accessibility results, and package verification should be downloadable workflow artifacts. Only synthetic, redacted evidence belongs in Git. Private profiles, raw reports, downloads, videos with identifiers, and extension IDs must stay outside the repository.
