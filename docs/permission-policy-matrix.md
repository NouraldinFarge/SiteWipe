## Consent model shared by privileged features

Every run begins with a read-only preflight that does not request missing host access. With the default setting, **Review cleanup** initiates that work, shows the complete Standard/Expert scope and exact required patterns, and only its final approval may continue. With the separately confirmed, default-off direct setting, entering or selecting a valid target completes the hidden preflight and durable prompt-pending lease before **Clean now** becomes actionable. If exact access is pregranted, final detailed approval or direct **Clean now** submits cleanup in one SiteWipe activation. If a normal-source run is missing exact access, that first activation instead durably arms the reviewed approval, awaits the worker's exact nonce-bound acknowledgement, and opens or focuses one exact extension-owned handoff tab in the reviewed normal source window without invoking `permissions.request()` or starting cleanup. A second fresh activation occurs only in that worker-created tab's exact top-frame packaged document after the worker binds its tab/window/URL/origin and unique normal `TAB` `contextId` and returns a separate raw capability only to page memory. Direct-open, duplicate, reload, navigation, replacement, replay, or private/wrong-context pages fail closed. Closing the popup does not transfer its preparation capability: a replacement popup is recovery-locked while the armed record is admitted or reconciled. Permission possession and permission events are never cleanup authority. A private-source direct run requires **Allow in incognito** and pre-existing exact target access before preflight and never requests a missing pattern. Before any mutation, the short-lived, single-use approval mode must equal the mode derived from strict current settings; resolved target/associated scope, source/private context, browser private-access state, complete impact/permission/file-ID snapshot, armed nonce, exact handoff binding, both independent grant proofs, and permission lease must reconstruct exactly. Direct payloads must truthfully claim no per-run acknowledgements or typed file phrase, and there is no caller skip flag or raw cleanup route.

Review expiry revokes cleanup authority but is not proof that an invoked browser-controlled prompt settled. Ordinary in-session expiry, alarm, startup, late-grant, and maintenance handling must retain the non-runnable prompt tombstone and lease until authenticated exact terminal handoff settlement or a real browser-session boundary. If the exact event plus handoff-document-authenticated literal-true/pre-request-absence proof becomes complete after expiry, SiteWipe must run no cleanup, reconcile only the exact patterns classified temporary by that preflight, and durably return a nonce-bound terminal cancellation. Any shorter wording such as “expiry/maintenance reconciles” in the matrix below means this conservative process; current access absence alone never permits in-session discard while the native prompt can still settle.

## Least-privilege conclusions

- There is no required host pattern and no required `<all_urls>` authority. Optional declarations are broad only because Chrome requires manifest-declared superset patterns; runtime requests use preflight-derived exact subsets. Any broader/all-site grant already present in the browser is separately inventoried, displayed in detailed mode or report-labeled in direct mode, preserved, and never treated as permission to broaden cleanup.
- `webNavigation` is genuinely optional with documented degraded behavior. In Expert mode, one explicit action requests access and leaves embedded discovery off; a later separate setting save enables the feature. Disabling an enabled feature—including by switching it to Standard—explicit removal, and settings reset persist discovery off and release access. Entering Expert keeps the feature off, and unrelated saves while it was already off preserve existing access without inferring grant ownership. The ten named permissions support current product features; making history, downloads, side panel, alarms, or DNR optional/removing them requires a coherent UX and behavior change, not a manifest-only edit.
- Required `sessions` and `contentSettings` were removed. The extension declares no bookmarks, identity, management, native-messaging, clipboard, geolocation, notification, password/passkey, or sync-storage permission.
- Incognito access is browser-controlled by `"incognito": "spanning"`; it is not a named permission SiteWipe can grant. Private-source cleanup fails if access or exact target permission is absent before preflight, and direct mode does not prompt for that missing permission. The state must remain equal at token consumption and is immutable for the run, so normal-only authority cannot expand into private tabs. Completed reports are not persisted whenever private access is enabled or private context is observed.
- Every permission and host declaration is tied to the extension's single purpose: reviewing and attempting guarded cleanup of browser-exposed data for one user-approved site boundary. No permission may be retained for speculative future use.
