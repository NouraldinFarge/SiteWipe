## Consent model shared by privileged features

Every run begins with a read-only preflight that does not request missing host access. With the default setting, **Review cleanup** initiates that work, shows the complete Standard/Expert scope and exact required patterns, and only its final approval may continue. With the separately confirmed, default-off direct setting, entering or selecting a valid target completes the hidden preflight and durable prompt-pending lease before **Clean now** becomes actionable. One **Clean now** activation may continue with `settings_direct`; a normal-source continuation may still trigger a separate native Chrome/Brave host-access confirmation. A private-source direct run requires **Allow in incognito** and pre-existing exact target access before preflight and never requests a missing pattern. Before any mutation, the short-lived, single-use approval mode must equal the mode derived from strict current settings; resolved target/associated scope, source/private context, browser private-access state, complete impact/permission/file-ID snapshot, and permission lease must reconstruct exactly. Direct payloads must truthfully claim no per-run acknowledgements or typed file phrase, and there is no caller skip flag or raw cleanup route.

## Least-privilege conclusions

- There is no required host pattern and no required `<all_urls>` authority. Optional declarations are broad only because Chrome requires manifest-declared superset patterns; runtime requests use preflight-derived exact subsets. Any broader/all-site grant already present in the browser is separately inventoried, displayed in detailed mode or report-labeled in direct mode, preserved, and never treated as permission to broaden cleanup.
- `webNavigation` is genuinely optional with documented degraded behavior. Standard mode, entry into Expert, feature disable, and settings reset persist embedded discovery off and release the permission; enabling it requires a later explicit Expert gesture. The ten named permissions support current product features; making history, downloads, side panel, alarms, or DNR optional/removing them requires a coherent UX and behavior change, not a manifest-only edit.
- Required `sessions` and `contentSettings` were removed. The extension declares no bookmarks, identity, management, native-messaging, clipboard, geolocation, notification, password/passkey, or sync-storage permission.
- Incognito access is browser-controlled by `"incognito": "spanning"`; it is not a named permission SiteWipe can grant. Private-source cleanup fails if access or exact target permission is absent before preflight, and direct mode does not prompt for that missing permission. The state must remain equal at token consumption and is immutable for the run, so normal-only authority cannot expand into private tabs. Completed reports are not persisted whenever private access is enabled or private context is observed.
- Every permission and host declaration is tied to the extension's single purpose: reviewing and attempting guarded cleanup of browser-exposed data for one user-approved site boundary. No permission may be retained for speculative future use.

## Current policy assessment

The reviewed runtime is designed around a narrow single purpose, local-only processing, self-contained MV3 code, user-initiated site-specific access, default detailed review, and an explicitly warned opt-in direct path with truthful reporting. The owner selected MIT and confirmed the recorded provenance statement. Store readiness is still blocked by installed evidence, exact dashboard disclosures, a stable privacy-policy URL/contact, authentic media, exact-version approval, remote controls, and final human approval. ChatGPT in-app Browser synthetic UI evidence cannot satisfy installed permission-prompt, private-window, file-system, or extension-API rows in this matrix. No official AI-assisted-development disclosure requirement was identified in the reviewed first-party sources; that is a dated search result, not a promise about future dashboard requirements. Recheck all official pages and the live dashboard immediately before submission.
