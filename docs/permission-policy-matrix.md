# Permission and Chrome Web Store policy matrix

> **Public-source prerelease candidate undergoing safety, privacy, accessibility, and binary-release validation.**

Last reviewed: 2026-08-17 against the manifest, runtime call sites, and the dated official-source ledger at [`docs/evidence/policy-source-ledger-2026-08-17.json`](./evidence/policy-source-ledger-2026-08-17.json). This is a technical policy review, not store approval. Dashboard wording and browser prompts must be rechecked at submission time.

## Consent model shared by privileged features

Read-only preflight is initiated by **Review cleanup** and does not request missing host access. Both Standard and Expert mode then display a complete per-run review. Only the explicit final approval may request the missing displayed target patterns and submit cleanup. The native Chrome/Brave host-access prompt is separate and is never treated as cleanup consent. The consumed approval is short-lived, single-use, bound to the exact target/settings/scope/context/impact/permissions/file IDs, and independently required to be `detailed_review` before cleanup orchestration begins.

## Least-privilege conclusions

- There is no required host pattern and no required `<all_urls>` authority. Optional declarations are broad only because Chrome requires manifest-declared superset patterns; runtime requests use preflight-derived exact subsets.
- `webNavigation` is genuinely optional with documented degraded behavior. The ten named permissions support current product features; making history, downloads, side panel, alarms, or DNR optional/removing them requires a coherent UX and behavior change, not a manifest-only edit.
- Required `sessions` and `contentSettings` were removed. The extension declares no bookmarks, identity, management, native-messaging, clipboard, geolocation, notification, password/passkey, or sync-storage permission.
- Incognito access is browser-controlled by `"incognito": "spanning"`; it is not a named permission SiteWipe can grant. Private-source cleanup fails if access is disabled, and completed reports are not persisted whenever private access is enabled or private context is observed.
- Every permission and host declaration is tied to the extension's single purpose: reviewing and attempting guarded cleanup of browser-exposed data for one user-approved site boundary. No permission may be retained for speculative future use.

## Current policy assessment

The reviewed runtime is designed around a narrow single purpose, local-only processing, self-contained MV3 code, user-initiated site-specific access, and transparent destructive review. The owner selected MIT and confirmed the recorded provenance statement. A public, byte-matched privacy-policy Gist and non-sensitive comment route now exist; store readiness is still blocked by confidential reporting/support, installed evidence, exact dashboard disclosures, authentic media, exact-version approval, remaining remote controls, and final human approval. No official AI-assisted-development disclosure requirement was identified in the reviewed policy sources; that is a dated search result, not a promise about future dashboard requirements.
