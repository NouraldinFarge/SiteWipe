## Evidence wording rules

- Use “designed to” for architecture not yet browser-validated.
- Use “the guard rejects” only with a direct test reference.
- Use “tested on” only with an exact browser version, date, artifact hash, fixture, and retained result.
- Label ChatGPT in-app Browser results “synthetic UI evidence”; never cite them as an installed extension, native permission prompt, incognito, MV3 lifecycle, privileged API, Chrome-compatibility, or Brave-compatibility result.
- Use “best-effort verification covers” for exposed post-clean queries.
- Never turn a checksum into a signature claim or a zero exposed-residue result into complete erasure.
- Update this table whenever a claim, code path, browser result, artifact hash, or owner decision changes.
