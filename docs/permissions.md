# Permission threat model

> **Public-source prerelease candidate undergoing safety, privacy, accessibility, and binary-release validation.**

The manifest has no required host pattern. Read-only preflight does not request host access. Detailed review is the default in Standard and Expert mode. When the separately confirmed, default-off direct setting is enabled, entering or selecting a valid target completes the same hidden read-only preflight and durable prompt-pending lease before **Clean now** is enabled. With every exact target pattern pregranted, detailed final approval or direct **Clean now** submits the prepared single-use cleanup request in one SiteWipe activation. When a normal-source run is missing exact access, the first activation instead sends `armCleanupApproval` and awaits the worker's exact durable, nonce-bound acknowledgement; it invokes no permission request and starts no cleanup. The worker then creates or focuses one exact extension-owned handoff tab. A second fresh activation in that exact bound document dispatches authenticated non-runnable begin intent, synchronously starts `permissions.getAll()`, immediately invokes `permissions.request()` for only the missing target-specific `http` and `https` patterns, and dispatches authenticated invocation confirmation before awaiting the native result. Chrome/Brave controls the separate native confirmation.

The popup preparation capability remains bound to the exact worker-resolved popup context. After durable arming, the worker records a newly created tab ID before navigating it to the static packaged handoff URL. Only that top-frame extension document at the exact URL, origin, tab ID, and one unique worker-resolved `TAB` `contextId` may claim the record. Optional `runtime.MessageSender.documentId` may be cross-checked when present but is never required and cannot substitute for `contextId`. The worker mints a separate 256-bit handoff capability, persists only its SHA-256 digest, and returns the raw capability only to that page's memory; the static URL/history and extension storage contain no raw capability, nonce, token, target, or host pattern. Direct-open, copy, duplicate, reload, navigation, replacement, wrong-frame/tab/context, replay, and expiry fail closed. A newly opened popup remains recovery-locked while the record settles.

The exact armed record, begin intent, and confirm-created `promptInvocation` are non-runnable without two separate grant proofs. During activation two, the bound handoff document dispatches begin, synchronously starts `permissions.getAll()` immediately before `permissions.request()`, and dispatches invocation confirmation before awaiting. It may send the authenticated grant outcome only if the request resolves literal `true` and the pre-request inventory validly proves that none of the reviewed temporary origins was already exact- or broad-covered. Its authenticated payload and durable state must contain `preRequestTemporaryOriginsAbsent: true`. Independently, `permissions.onAdded` may record `promptGrant.complete` only for one exact host-only event equal to the complete reviewed temporary-origin set after begin. Readiness, atomic consumption, takeover, and prompt-owned permission removal require both proofs and the absence field. Lease schema 3 records `reviewed_prompt_grant` only after that complete session proof is durable, upgrades it to `admitted_cleanup` on admission, and carries it through `release_pending`. A true-only partial proof remains pending and non-runnable after bounded retries so a delayed exact event may complete it. Review expiry immediately revokes cleanup authority, but it does not prove that an invoked native prompt settled: ordinary in-session expiry, alarm, startup, late-grant, and maintenance paths retain the non-runnable prompt tombstone and lease even if access is currently absent. Only an authenticated exact terminal handoff settlement or a real browser-session boundary may discard that unresolved ownership record. If both exact proofs arrive after expiry, SiteWipe starts no cleanup, reconciles only the exact preflight-classified temporary patterns, and durably returns the nonce-bound terminal cancellation. Invalid, malformed, or already-covering inventory creates no outcome authority; authenticated denial, dismissal, abandonment, and synchronous `not_invoked` settle only their exact terminal path. An intersecting `permissions.onRemoved` event revokes ownership and invalidates pending review authority, so later manual regrant is never treated as SiteWipe-owned. Proofless, legacy, and revoked access is preserved. An unconfirmed begin has a separate 30-second confirmation alarm without changing the five-minute review expiry.

Preflight inspects granted host patterns but retains only a privacy-minimized inventory of the exact required grants and relevant broader/all-site pre-existing patterns that cover the target. Detailed review displays broader grants; direct mode binds them and reports them after the run. Unrelated exact or wildcard hostnames are omitted. Before a normal-window prompt can occur, SiteWipe stores a durable lease that classifies each exact requested pattern as pre-existing or temporary. Private-source cleanup requires browser-controlled **Allow in incognito** and exact target access before preflight and refuses to request or persist a missing private target pattern. Completion, failure, cancellation, abandonment, restart recovery, maintenance, and extension-local reset may release only temporary exact patterns backed by complete reviewed/admitted ownership proof. Review expiry revokes cleanup authority but does not itself release or forget an invoked prompt's lease. A confirmed SiteWipe-owned grant remains recorded until strict browser queries prove every temporary pattern absent; an unresolved invoked prompt remains recorded until exact terminal handoff settlement or a real browser-session boundary, at which point incompletely proved access is preserved. Every exact or broader pre-existing user-controlled grant is preserved. Browser policy or user choice can withhold access, in which case no cleanup request is accepted.

Late-grant terminalization is ordered and crash-safe. After strict inventory and exact reconciliation prove the temporary patterns absent (or prove that externally controlled access must be preserved), SiteWipe commits and rereads the nonce-bound canceled result before deleting the matching review and lease. A failed pre-commit terminal write therefore leaves non-runnable recovery evidence intact, while a commit-then-reject can replay only the identical durable result.

Chrome host-permission declarations are necessarily pattern-based. The preflight-bound patterns are derived from the normalized registrable site or exact origin and every adapter repeats the target matcher. Browser-level storage is additionally constrained by the explicit partition policy: registrable-site cleanup includes third-party page storage partitioned beneath the selected top-level site, while exact-origin-only browser-level closed-page storage/cache is skipped. Possession of permission and permission events are capability observations or wake signals, never cleanup authority and never authorization to broaden scope.

The durable lease accepts only canonical target patterns produced by the preflight target model. Its requested set must be the exact disjoint union of pre-existing and temporary exact patterns. The preflight `permissions.getAll()` inventory keeps only canonical required exact and relevant broader patterns, derives coverage, and omits unrelated hosts. Before a native prompt can open, the first **Clean now** or detailed approval activation durably arms only the exact reviewed approval; the worker creates or focuses the exact extension-owned handoff tab after that arm. A second fresh activation occurs only in the tab's bound handoff document. That document dispatches authenticated begin, synchronously starts `permissions.getAll()` immediately before `permissions.request()`, and immediately dispatches authenticated invocation confirmation, all before awaiting. Begin and confirmation alone never run cleanup. After the awaited values settle, a missing, rejected, malformed, or already-covering inventory settles abandoned, records no outcome, preserves access, and starts no cleanup. Only a literal `true` request paired with a valid inventory proving all reviewed temporary origins absent may send the handoff-capability-authenticated grant outcome; the worker binds `{ contextId, granted: true, preRequestTemporaryOriginsAbsent: true, recordedAtMs }` to the exact worker-created tab/document. Separately, `permissions.onAdded` must provide one exact canonical host-only event equal to the complete temporary set before `promptGrant.complete` is recorded. Readiness, atomic consumption, takeover, and prompt-owned removal require `promptInvocation`, both grant proofs, the literal absence field, exact tab/context/capability binding, and a matching schema-3 lease. After the complete handoff is durably stored, the lease moves from proofless to `reviewed_prompt_grant`; admission moves it to `admitted_cleanup`, while `release_pending` retains the proof across restart. A true-only partial proof remains pending after bounded retries; a later exact event may complete once. Review expiry revokes cleanup authority but ordinary in-session expiry/maintenance must keep an invoked prompt's tombstone and lease until authenticated exact terminal handoff settlement or a real browser-session boundary. A complete event/outcome/absence conjunction arriving after expiry authorizes no cleanup; it authorizes only exact temporary-access reconciliation and a durable terminal cancellation result. Any intersecting `permissions.onRemoved` event serially marks ownership `revoked` and invalidates pending authority, preventing a later manual regrant from completing or being removed under stale proof. Startup preserves unresolved invoked-prompt records, discards only terminal legacy/proofless/revoked bookkeeping while preserving its access, and retries removal only for reviewed/admitted provenance. The dedicated 30-second confirmation alarm remains separate from five-minute review expiry. Only the worker may release temporary exact origins backed by current complete proof; ambiguous submissions preserve access and visible recovery state.

| `sessions`            | Chrome exposes recently closed entries but no targeted forget API; extra discovery did not justify default authority.                               |
| `contentSettings`     | Arbitrary user/enterprise/other-extension rules cannot be safely deleted per target; the legacy migration no longer justifies permanent permission. |

`webNavigation` moved from required to optional. No permission for bookmarks, identity, passwords, management, native messaging, geolocation, clipboard, notifications, or `storage.sync` is declared.

## Incognito/private access

`"incognito": "spanning"` does not grant private access. The user must enable **Allow in incognito** in the browser extension settings. A cleanup originating in a private window is rejected if the browser says access is disabled or if exact target access is missing before preflight; the direct path does not request that missing access. The private-access state is exact-compared when the approval token is consumed and then carried immutably through discovery, page injection, tab changes/closure, progress overlays, and verification; normal-only authority cannot expand into private tabs. Whenever private access is enabled, the completed report is transient and is not persisted because affected private scope cannot be proven absent.

## Browser API caveats

- For registrable-site targets, `browsingData.remove({ origins })` selects third-party LocalStorage, IndexedDB, Cache Storage, file-system data, service workers, and related page storage partitioned beneath the selected top-level site. The same data owner's partitions beneath unrelated top-level sites are not selected; partitions owned by the selected origin beneath unrelated top-level sites may remain.
- Chrome/Brave partition browser storage by schemeful top-level site without a port boundary. Exact-origin-only browser-level closed-page storage/cache is therefore skipped; exact live-page cleanup still runs and closed-page residue is reported as partial or unavailable.
- Cookie scope is a separate host-based path and does not include ports, so local exact-origin review states that cookie cleanup is host-scoped. An out-of-domain CHIPS cookie is not brought into scope merely because its partition key names the selected site.
- SessionStorage follows the browsing context and is reported separately from persistent LocalStorage/IndexedDB partition evidence.
- Partitioned-cookie visibility and removal keys vary by Chrome version and store; attempts and uncertainty are reported.
- Named permissions are install-time authority even when a feature is disabled in settings. Further optionalization requires an end-to-end UX and failure-semantics redesign, not a manifest-only change.
