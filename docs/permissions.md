# Permission threat model

> **Public-source prerelease candidate undergoing safety, privacy, accessibility, and binary-release validation.**

The manifest has no required host pattern. Read-only preflight does not request host access. Detailed review is the default in Standard and Expert mode. Its explicit final approval asks only for missing target-specific `http` and `https` patterns before submitting the single-use cleanup request. When the separately confirmed, default-off direct setting is enabled, entering or selecting a valid target completes the same hidden read-only preflight and durable prompt-pending lease before **Clean now** is enabled. One **Clean now** action may then request missing patterns for a normal-source `settings_direct` run and submit the prepared token. Chrome/Brave controls its own permission prompt, so the browser may require an additional browser-controlled interaction after the one SiteWipe action.

Preflight inspects granted host patterns but retains only a privacy-minimized inventory of the exact required grants and relevant broader/all-site pre-existing patterns that cover the target. Detailed review displays broader grants; direct mode binds them and reports them after the run. Unrelated exact or wildcard hostnames are omitted. Before a normal-window prompt can occur, SiteWipe stores a durable lease that classifies each exact requested pattern as pre-existing or temporary. Private-source cleanup requires browser-controlled **Allow in incognito** and exact target access before preflight and refuses to request or persist a missing private target pattern. Completion, failure, cancellation, abandonment, expiry, restart recovery, maintenance, and extension-local reset attempt to release only temporary exact patterns. The lease is retained until strict browser queries prove those patterns absent; every exact or broader pre-existing user-controlled grant is preserved. Browser policy or user choice can withhold access, in which case no cleanup request is accepted.

## Optional permissions

| Permission                                | Trigger                                                                                                                                 | Behavior without it                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webNavigation`                           | User separately enables Expert embedded-frame discovery through a permission request                                                    | Top-level/open-frame data exposed through other paths remains available; embedded target frames may be missed and are reported as a limitation. Switching to Standard, entering Expert from Standard, disabling the feature, or resetting settings persists it off and releases the optional named permission; entering Expert never silently revives a prior grant.                                           |
| `http://*/*`, `https://*/*` host patterns | A normal-source detailed final approval or direct **Clean now** preflight needs a normalized target pattern that is not already granted | Preflight remains non-destructive. Withholding stops before the cleanup message. Newly granted patterns are durably tracked through completion/cancellation/abandonment/expiry/reset/restart and the record is forgotten only after absence is proved; each pre-existing pattern is preserved. A private-source direct run requires exact target access before preflight and never requests a missing pattern. |

Chrome host-permission declarations are necessarily pattern-based. The preflight-bound patterns are derived from the normalized registrable site or exact origin and every adapter repeats the target matcher; possession of permission is not treated as authorization to broaden cleanup.

The durable lease accepts only canonical target patterns produced by the preflight target model. Its requested set must be the exact disjoint union of pre-existing and temporary exact patterns. The separate `permissions.getAll()` inventory keeps only canonical required exact and relevant broader patterns, derives which required patterns are covered by broader access, and reports whether the relevant observed grants cover all HTTP and HTTPS sites. Unrelated exact/wildcard hosts are omitted from the detailed review, session approval, and report. The inventory is preflight-bound and report-visible, but broader patterns never enter an automatic removal call. Before **Clean now** or detailed final approval can open a native prompt, the lease is armed as `prompt_pending`; the five-minute approval is never extended on popup reopen, while a separate conservative 30-minute recovery window prevents a late native grant from outliving ownership evidence. Broad wildcard-only lease entries, protected browser-service scopes, malformed relationships, invalid timestamps/statuses, and unknown records fail closed before any permission API mutation. When Chrome's native prompt returns after the popup's clock has crossed review expiry, the popup cannot infer from that clock alone whether cleanup was admitted. It first asks the worker to reconcile the authenticated capability/nonce-bound handoff. A matching running job or terminal report proves that admission crossed before the deadline and must be rendered truthfully. Only a matching canceled result with `cleanupStarted: false`, `temporaryAccessReleased: true`, and strict proof that the temporary origins are absent and the recovery record was removed may say that no cleanup started and access was released. An unknown result retains the popup binding, locks another cleanup, and directs the user to the current job/report or Options without claiming either admission or release. For a rejected or otherwise non-runnable handoff, the popup may submit terminal settlement, but only the worker may release the preflight-classified temporary exact origins; the popup never removes permissions directly. An ambiguous or timed-out submission does not trigger speculative removal. If Chrome refuses removal or permission state cannot be queried, Options reports recovery pending and the user can retry maintenance or revoke access manually.

## Permissions removed during this audit

| Removed permission    | Reason                                                                                                                                              |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Required `<all_urls>` | Replaced with user-gesture, target-specific optional host access.                                                                                   |
| `sessions`            | Chrome exposes recently closed entries but no targeted forget API; extra discovery did not justify default authority.                               |
| `contentSettings`     | Arbitrary user/enterprise/other-extension rules cannot be safely deleted per target; the legacy migration no longer justifies permanent permission. |

`webNavigation` moved from required to optional. No permission for bookmarks, identity, passwords, management, native messaging, geolocation, clipboard, notifications, or `storage.sync` is declared.

## Incognito/private access

`"incognito": "spanning"` does not grant private access. The user must enable **Allow in incognito** in the browser extension settings. A cleanup originating in a private window is rejected if the browser says access is disabled or if exact target access is missing before preflight; the direct path does not request that missing access. The private-access state is exact-compared when the approval token is consumed and then carried immutably through discovery, page injection, tab changes/closure, progress overlays, and verification; normal-only authority cannot expand into private tabs. Whenever private access is enabled, the completed report is transient and is not persisted because affected private scope cannot be proven absent.

## Browser API caveats

- `browsingData` origin scoping is not uniform across all data types; only preflight-bound, origin-capable categories are passed to the adapter.
- Cookie scope does not include ports, so local exact-origin review states that cookie cleanup is host-scoped.
- Partitioned-cookie visibility and removal keys vary by Chrome version and store; attempts and uncertainty are reported.
- Named permissions are install-time authority even when a feature is disabled in settings. Further optionalization requires an end-to-end UX and failure-semantics redesign, not a manifest-only change.
