# Permission threat model

> **Private release candidate undergoing safety, privacy, accessibility, and release-readiness validation.**

The manifest has no required host pattern. Read-only preflight does not request host access. Both Standard and Expert mode display a complete per-run review. Only its explicit final approval asks for missing target-specific `http` and `https` patterns and then submits the single-use detailed-review cleanup request. Chrome/Brave controls its own permission prompt, so the browser may require a second browser-controlled interaction; that prompt is not cleanup consent. Before a prompt can occur, SiteWipe stores a durable lease that classifies each requested pattern as pre-existing or temporary. Completion, failure, cancellation, expiry, restart recovery, maintenance, and extension-local reset attempt to release only temporary patterns. The lease is retained until strict browser queries prove those patterns absent; pre-existing patterns are always preserved. Browser policy or user choice can withhold access, in which case no cleanup request is sent.

## Required named permissions

| Permission              | Why it is present                                                                           | Abuse potential                                             | Runtime containment / alternative considered                                                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `browsingData`          | Origin-list removal for allowlisted cache/storage types                                     | Profile-wide removal if called with time or without origins | A guard accepts only canonical preflight-bound origins, forbids `since`, and allowlists types. Removing it would eliminate core origin-storage cleanup.                                                                                                              |
| `cookies`               | Discover and remove matching unpartitioned/partitioned cookies                              | Read/change cookies for hosts the extension can access      | JIT host access limits reachable sites; candidate matching, query count, stores, partitions, and paths are bounded.                                                                                                                                                  |
| `tabs`                  | Identify active target, inspect matching tabs, show progress, and close target-matched tabs | Observe tab metadata and close tabs                         | Matching is target-constrained; `activeTab` alone cannot support multi-tab discovery/closing or later verification.                                                                                                                                                  |
| `history`               | Find and delete individual matching history URLs                                            | Observe/delete browsing history                             | Queries are bounded and every returned URL is re-matched. Making it optional was considered, but history cleanup is a default category; a future capability-selectable model could revisit this.                                                                     |
| `downloads`             | Find/erase matching download-list records; optional on-disk file deletion                   | Observe download metadata and delete files                  | Record URLs are re-matched. File deletion is Expert-only, off by default, bound to preflight-captured completed IDs, freshly revalidated, and separately confirmed by typing the normalized target. A separate build/optional permission remains a future prototype. |
| `storage`               | Settings, sanitized reports, job/shield/temporary-access recovery, and session approval     | Retain sensitive local metadata                             | Safe defaults, central scrubbing, schemas, serialized mutations, bounds, redaction, expiry, no completed-report persistence while private access is enabled, and reset/forget controls. `storage.sync` is never used.                                                |
| `scripting`             | Isolated-world live-page scrub and progress overlay                                         | Execute code in permitted pages                             | Only bundled functions, no MAIN world, target check inside injection, and JIT host permission. Removing it would drop live-page and overlay behavior.                                                                                                                |
| `declarativeNetRequest` | Temporary target request shield while cleanup runs                                          | Block traffic                                               | Session rules only, reserved IDs `730000–730499`, target-bound URL filters, persist-before-mutate, full-range diagnostics/recovery. No static global rules.                                                                                                          |
| `sidePanel`             | Detailed report/capability view                                                             | Opens extension UI                                          | No page-data authority. Could be replaced by a tab, but the side panel preserves context with negligible security expansion.                                                                                                                                         |
| `alarms`                | Expire reports/shields and recover stale jobs after worker suspension                       | Wake the service worker                                     | Fixed extension-owned alarms and idempotent maintenance only; no network activity.                                                                                                                                                                                   |

## Optional permissions

| Permission                                | Trigger                                                                                             | Behavior without it                                                                                                                                                                                                                                                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webNavigation`                           | User enables Expert embedded-frame discovery through a permission request                           | Top-level/open-frame data exposed through other paths remains available; embedded target frames may be missed and are reported as a limitation.                                                                                                                                    |
| `http://*/*`, `https://*/*` host patterns | Final approval of the complete review needs a normalized target pattern that is not already granted | Preflight remains non-destructive. Withholding stops before the cleanup message. Newly granted patterns are durably tracked through completion/cancellation/expiry/reset/restart and the record is forgotten only after absence is proved; each pre-existing pattern is preserved. |

Chrome host-permission declarations are necessarily pattern-based. The preflight-bound patterns are derived from the normalized registrable site or exact origin and every adapter repeats the target matcher; possession of permission is not treated as authorization to broaden cleanup.

The durable lease accepts only canonical target patterns produced by the reviewed target model. Its requested set must be the exact disjoint union of pre-existing and temporary patterns. Broad wildcard-only patterns, protected browser-service scopes, malformed relationships, invalid timestamps/statuses, and unknown records fail closed before any permission API mutation. If Chrome refuses removal or permission state cannot be queried, Options reports recovery pending and the user can retry maintenance or revoke access manually.

## Permissions removed during this audit

| Removed permission    | Reason                                                                                                                                              |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Required `<all_urls>` | Replaced with user-gesture, target-specific optional host access.                                                                                   |
| `sessions`            | Chrome exposes recently closed entries but no targeted forget API; extra discovery did not justify default authority.                               |
| `contentSettings`     | Arbitrary user/enterprise/other-extension rules cannot be safely deleted per target; the legacy migration no longer justifies permanent permission. |

`webNavigation` moved from required to optional. No permission for bookmarks, identity, passwords, management, native messaging, geolocation, clipboard, notifications, or `storage.sync` is declared.

## Incognito/private access

`"incognito": "spanning"` does not grant private access. The user must enable **Allow in incognito** in the browser extension settings. A cleanup originating in a private window is rejected if the browser says access is disabled. Whenever private access is enabled, the completed report is transient and is not persisted because affected private scope cannot be proven absent.

## Browser API caveats

- `browsingData` origin scoping is not uniform across all data types; only preflight-bound, origin-capable categories are passed to the adapter.
- Cookie scope does not include ports, so local exact-origin review states that cookie cleanup is host-scoped.
- Partitioned-cookie visibility and removal keys vary by Chrome version and store; attempts and uncertainty are reported.
- Named permissions are install-time authority even when a feature is disabled in settings. Further optionalization requires an end-to-end UX and failure-semantics redesign, not a manifest-only change.
